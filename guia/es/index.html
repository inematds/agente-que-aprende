Kit · Claude Code y Codex · sin API

El error que vuelve se convierte en una traba

Tu agente se equivoca, lo corriges y al día siguiente vuelve a equivocarse igual. Este kit detecta dónde lo corregiste, identifica los errores que se repiten —incluso en otro proyecto— y convierte la lección en un gancho, validador o prueba que el modelo no puede saltarse.

En resumen

agente-que-aprende es un kit de cuatro scripts en Python para quienes trabajan con agentes de IA para programar, como Claude Code y Codex. Lee tus sesiones y los archivos donde registras fallas y lecciones (FALHAS.md, LESSONS.md), muestra dónde corregiste al agente y qué errores vuelven, y te ayuda a convertir cada lección en una traba automática en lugar de otra regla escrita. Solo requiere Python 3; no usa internet ni API, y ninguna regla se adopta sin tu decisión.

Qué es

El modelo es el mismo. El sistema que lo rodea mejora.

Una regla escrita es la corrección más débil: el modelo puede saltársela. El orden de fuerza es arquitectura (el error se vuelve imposible) > gancho/validador (bloquea) > prueba (detecta) > texto.

🔁 Retro de 1 minuto

retro.py lee la sesión y enumera cada vez que corregiste al agente y cada error de herramienta que se repitió, junto con el peldaño sugerido. Se ejecuta automáticamente cuando se cierra la sesión.

🪜 Subir un peldaño

degrau.py y jardineiro.py leen FALHAS y LESSONS, agrupan el mismo error aunque esté escrito de distintas maneras y muestran qué sigue siendo solo texto y se repite.

🔒 Gancho que bloquea

gancho.py es un hook de Claude Code: cada lección se convierte en una línea de ganchos.json y se bloquea el comando que ya falló, con una explicación para el agente.

Cómo funciona

El ciclo y dónde entra cada script

El agente ejecuta, recibe una respuesta, se verifica esa respuesta, tú la apruebas y la lección queda donde la próxima ejecución no puede ignorarla.

Termina la sesión→ retro.py (correcciones + errores)→ Tú eliges (compuerta humana)→ FALHAS / LESSONS / SIL→ jardineiro.py semanal→ gancho, validador o prueba→ disminuye la reincidencia

Los 6 peldaños

1 protecciones (pruebas, tipos, lint) · 2 skills · 3 memoria · 4 error imposible · 5 automatización · 6 automejora. La cima es el último peldaño: sin los anteriores no hay nada que aprender.

Estimación transparente

El peldaño actual y la sugerencia se obtienen de palabras clave en aprende/comum.py ("ausente/pulou" (ausente/se saltó) → arquitectura; "conferir antes" (revisar antes) → validador; comando peligroso → gancho). Las palabras y los informes están en portugués (en parte, en inglés); puedes ajustar la lista y decidir.

Se integra con SIL Loop R

SIL Loop R es otro proyecto abierto: un cuaderno local (SQLite) de incidencias y lecciones en el que nada se convierte en regla sin una decisión humana. Con --sil <projeto>, cada propuesta del kit se agrega allí como incidencia + lección propuesta. Es opcional.

Requisitos previos

Solo Python 3

Sin dependencias, sin claves, sin llamadas a la red. SIL Loop R es opcional.

Python 3.10+

Solo biblioteca estándar.

# verificar
python3 --version

Tus registros

Archivos con estos nombres: FALHAS.md (tabla: fecha | qué falló | corrección mínima | prompt/infra), LICOES.md (tabla de 3 columnas) y/o LESSONS.md (lista "- regla (fecha)"). La fila de la tabla comienza con la fecha (AAAA-MM-DD o dd/mm).

# ejemplo de fila
| 2026-11-06 | render cayó: falta la plantilla | ejecutar el paso antes | prompt |

Opcional

Claude Code (para los hooks), systemd (temporizador semanal) y SIL Loop R (para recibir las propuestas). El kit busca SIL en ~/projetos/sil-loop-r/, en el PATH (sil) o en AQA_SIL.

git clone https://github.com/inematds/sil-loop-r.git ~/projetos/sil-loop-r
python3 ~/projetos/sil-loop-r/sil.py --project ~/projetos/meu-app init
Guía de uso · paso a paso

Del clon a la primera traba

Cada paso usa los comandos del repositorio. Las pruebas usan datos ficticios y se ejecutan sin conexión.

1

Descargar y probar

Las 10 pruebas verifican la lectura de las tablas, la retro, el gancho y la integración con SIL.

git clone https://github.com/inematds/agente-que-aprende.git && cd agente-que-aprende
python3 -m unittest discover -s tests -v   # OK
2

Ver qué puede subir un peldaño en un proyecto

Lee las fallas y lecciones del proyecto y enumera lo que se repite y sigue siendo solo texto, con el peldaño sugerido y las líneas de origen.

python3 degrau.py ~/projetos/meu-app/FALHAS.md ~/projetos/meu-app/LESSONS.md --top 10
3

Ejecutar el jardinero en todos los proyectos

Mide la reincidencia (cuántos registros corresponden al mismo error repetido), muestra los errores que "cambiaron de casa" y el ranking general.

python3 jardineiro.py --raiz ~/projetos --saida jardim/$(date +%F).md
4

Hacer la retro de una sesión

Indica el archivo de la sesión (las más recientes: ls -t ~/.claude/projects/*/*.jsonl | head -3). --pergunta agrega la solicitud de retro para pegarla en el agente ("¿qué salió mal aquí?").

python3 retro.py ~/.claude/projects/<pasta>/<id>.jsonl --pergunta
python3 retro.py ~/.codex/sessions/<aaaa/mm/dd>/rollout-<…>.jsonl   # Codex también
5

Convertir una lección en un gancho

Agrega un elemento a la lista de ganchos.json (separado por comas): el patrón del comando que falló, la excepción (opcional), el mensaje y el origen de la lección. Para no modificar el archivo del kit, usa un archivo propio en AQA_GANCHOS=/ruta/mios.json. Pruébalo antes de activar el paso 6: el gancho solo bloquea cuando se ejecuta el comando, no cuando se menciona en un texto o en un grep.

{"id": "pkill-f", "ferramenta": "Bash", "padrao": "\\bpkill\\b[^|;&]*\\s-f\\b",
 "mensagem": "Liste com pgrep -af e mate por PID em outro comando.", "origem": "FALHAS (7x)"}

echo '{"tool_name":"Bash","tool_input":{"command":"pkill -f x"}}' | python3 gancho.py; echo $?   # 2 = bloqueado
6

Activar en Claude Code

En ~/.claude/settings.json: el gancho antes de cada comando Bash y la retro al cerrar la sesión (informes en ~/.local/share/agente-que-aprende/retro/, solo si hubo una corrección o un error repetido).

"hooks": {
  "PreToolUse": [{"matcher": "Bash", "hooks": [{"type": "command", "command": "python3 /caminho/agente-que-aprende/gancho.py"}]}],
  "SessionEnd": [{"hooks": [{"type": "command", "command": "bash /caminho/agente-que-aprende/hooks/fim-de-sessao.sh"}]}]
}
7

Jardinero cada semana

Copia el temporizador y, en jardineiro.service, cambia KIT (dónde está el kit), SAIDA (dónde guardar los informes) y --raiz %h/projetos (dónde están tus proyectos). Cada lunes a las 07:30 se genera un informe nuevo.

cp modelos/systemd/jardineiro.{service,timer} ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now jardineiro.timer
8

Enviar las propuestas a SIL (opcional)

Con SIL instalado e iniciado en el proyecto (ver Requisitos previos), los primeros 5 candidatos se convierten en una incidencia + lección propuesta en SIL Loop R. No se adopta nada sin tu aprobación.

python3 jardineiro.py --raiz ~/projetos --sil ~/projetos/meu-app
Ejemplos

Lo que encontró en la primera pasada

Ejecutado sobre los registros reales de INEMA el 7/11/2026: 196 archivos de fallas y lecciones, 1.880 registros, en menos de 1 segundo.

El 10% es el mismo error otra vez

180 registros en 84 grupos de repetición; 57 grupos abarcan varios proyectos: el error solo cambió de casa.

pkill -f: 7× en 6 proyectos

Matar un proceso por patrón mataba al propio shell. Cada vez quedó registrada como una línea de texto. Ahora existe el gancho pkill-f: el comando se bloquea en el momento, con la forma correcta en el mensaje.

"Falta la plantilla" 4×

El render fallaba porque no se había ejecutado un paso anterior. Sugerencia del kit: arquitectura — la cadena genera lo que falta (modelos/validador-passo.sh).
